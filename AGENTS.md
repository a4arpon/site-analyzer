# AGENTS.md

Deno CLI ("webalyzer") that audits a website against a JSON rule pack and reports SEO / agent-readiness / accessibility / e-commerce findings. It crawls a URL, parses the HTML with `htmlparser2`, and runs declarative rules (`selector`, `header`, `regex`, `fetch`, `composite`, `jsonld`, `unique`, `pairing`, `sequence`) defined in `rules/*.json`. **The audit report is consumed by AI agents, not humans** — output includes fix instructions per finding.

## Stack & tooling (verified)
- Runtime: **Deno** (`deno 2.9.3`). All commands use the `deno` CLI, not `node`/`npm` despite `package.json` existing.
- `package.json` declares npm deps (`htmlparser2`, `css-select`, `domhandler`, `inquirer`) but they are consumed via Deno's Node compat. No `npm install` step is required to run or typecheck.
- Formatting/linting is **Deno's** (`deno fmt` / `deno lint`), configured in `deno.json`. `.zed/settings.json` also wires the Zed editor to Deno's formatter. Line width 80, no semicolons, spaces (not tabs).
- `"unstable": ["tsgo"]` is set — typecheck uses the `tsgo` (Go TS) backend.

## Commands
- Run an audit: `deno task dev --site=<url-or-spec> [--rule=<packs>] [--no-default-rule] [--output-type=<mode>]`. `dev` grants `--allow-net` + `--allow-read` (read for local rule packs). `--site` is required. **Site spec**: a plain URL audits ONLY that page (no robots/sitemap probes at all — see `src/site-spec.ts`); a URL containing `*`/`?` in its path triggers sitemap discovery + path filter (`*`/`**` both cross `/`, e.g. `--site=https://example.com/community-docs/*` crawls that subtree; 0 matches → warn + exit 0, never widens scope). Scheme optional (`example.com/x` → https). `--rule` is **optional**: local paths OR remote URLs, comma-separated. **Default pack**: the bundled `src/assets/core.json` (40 rules) is imported as a JSON module (embedded in compiled binaries) and runs on every audit — `--rule` packs merge ON TOP of it (later wins on ID collision), `--no-default-rule` excludes it. With `--no-default-rule` and no `--rule`, webalyzer runs nothing and prints a JSON array of suggested built-in skill packs (name/description/url pointing at raw GitHub rule packs) so an agent knows where to load skills from, then exits 0.
  - `--output-type`: `overview` (plain human summary, no color) | `info` (default, ANSI-colored agent report with why/fix/snippet) | `agent` (token-optimized `key=value` lines, logs→stderr) | `compact-agent` (heavily compressed pipe-delimited tokens, fix truncated to 80 chars, ~80% fewer tokens; progress→stderr). In `agent`/`compact-agent` modes stdout stays clean for machine parsing. Every report ends with an attribution footer (`AppBranding` in `src/config.ts`: maintainer + repo URL).
  - e.g. `deno task dev --site=https://example.com/about --rule=https://example.com/my-pack.json` (single page, your pack on top of default core)
  - e.g. `deno task dev --site=https://example.com/community-docs/* --output-type=compact-agent` (scoped subtree, bundled core only)
  - `--rule` accepts **comma-separated packs** that merge into one run: `--rule=./src/assets/e-commerce.json,./my-pack.json` (later pack wins on rule-ID collision — see `loadRulePacks`), always merged after the default core unless `--no-default-rule`.
  - with `--no-default-rule` and no `--rule`: prints suggested skills and exits 0 (no audit).
- Compile standalone binaries: `deno task build:compile` → `./dist/web-analyzer-qjs` (QuickJS) and `deno task build:compile-v8` → `./dist/web-analyzer-v8` (V8) (`.gitignore`d via `dist/*`). The default pack is embedded at compile time (JSON import in `src/app.ts`) — binaries run from any cwd with no files on disk.
- Lint: `deno lint` — scope is `./src/*` only.
- Format: `deno fmt`.
- Typecheck: `deno check src/app.ts` (or any entry).
- No test task is defined; there is no test suite yet.

## Architecture
- Entrypoint: `src/app.ts` — parses `--site` / `--rule` / `--output-type`, resolves scope via `src/site-spec.ts`, builds `RuleCheckerEngine`, prints `formatReport(result, type)` (all four renderers end with an attribution footer).
- `src/config.ts` — **single source of engine defaults + score weights + branding**. `EngineDefaults` (timeout, UA, concurrency, batch size) and `ScoreWeights` (P0=50, P1=30, P2=15, P3=4). `AppConfig` holds product name (`webalyzer`) + User-Agent. `AppBranding` = maintainer + GitHub/repo URLs (rendered in every report footer + usage text). Edit here, not in engine/display.
- `src/site-spec.ts` — `parseSiteSpec` / `matchPath`: the `--site` spec language. Plain URL → single-page audit (sitemap discovery NEVER runs); path glob (`*`/`**` cross `/`, `?` single char) → sitemap discovery + path filter. Origin fixed by spec, match on pathname only, scheme optional.
- `src/crawler.ts` — owns `crawl()` + `fetchWithRetry()` + `CrawledPage` type + `discoverUrls()` (sitemap-aware URL discovery: robots.txt `Sitemap:` + `/sitemap.xml` + `/sitemap_index.xml`, recursive sitemap-index parsing, depth-guarded). Engine/app delegates to it. Single home for fetch/retry/timeout/sitemap logic.
- `src/rules-loader.ts` — `loadRulePacks(spec)`: comma-separated sources → `loadRulePack(source)` each (local path OR remote URL, `JSON.parse` + lightweight structural validation: metadata fields, rule-ID pattern `^[A-Z]{2,6}-\d{2,3}$`, key/id match, required check fields, valid `check.type`). `mergeRulePacks` unions rules (later pack wins on collision, warns) and takes metadata from the first pack. Throws clear errors on bad packs.
- `src/app.ts` — `BUILTIN_SKILLS`: catalog of suggested rule packs (name/description/url → raw GitHub URLs). When `--rule` is absent, webalyzer prints this array as JSON and exits 0 (no audit). This is the agent-discovery mechanism for "where do I load skills".
- `src/engine.ts` — orchestration + the 10 check type implementations (`selector`/`header`/`regex`/`fetch`/`composite`/`jsonld`/`unique`/`pairing`/`sequence`/`script`) + `extractSelectorValue` / `meetsThreshold` / `createFinding` / `calculateStats`. `calculateStats` computes a 0–100 health score (start 100, subtract `ScoreWeights` per finding, floor 0) + letter grade via `scoreToGrade`. `auditMany` is non-async (returns `Promise.all`). DOM parse is cached per page; element-count log line is debug-gated (full-tree scan).
- `src/display.ts` — `formatReport(result, type)`: dispatcher over four renderers, appends the attribution footer (`footerFor`). `formatText` = `info` (colorized, why/fix/snippet). `formatOverview` = plain human summary (no color). `formatAgent` = token-optimized `key=value` lines. `formatCompactAgent` = heavily compressed pipe-delimited tokens (`R|...` header, `$|pri|id|title|fix` per finding, fix truncated to 80 chars, `#|maintainer|repo` footer). Machine modes emit progress to stderr only.
- `src/rules.ts` — `OfficalRulesSDK`, a read-only accessor over a rule pack (spelled "Offical" in the source — do not "fix" the spelling without renaming usages).
- `src/updater.ts` — labeled home for the future pack self-update feature (currently a stub returning a placeholder). Not built.
- Rule packs: `src/assets/core.json` (default everything pack, 40 rules: SEO/OG/JSON-LD + `AXS-*` accessibility + `AG-*` agent navigability — imported by `src/app.ts`, embedded in binaries, runs unless `--no-default-rule`), `src/assets/e-commerce.json` (commerce add-on, 3 rules: `JSONLD-02` Product / `JSONLD-04` Offer / `JSONLD-05` BreadcrumbList — `--rule` merges it ON TOP of the default core), and `src/assets/business.json` (business add-on, 8 rules: `BIZ-01..08` — Organization url/sameAs/contactPoint, address completeness conditional, mailto/freemail/contact/about/privacy link checks). Plus `src/assets/schema.json` (JSON-Schema draft-07 validating the pack format; `$id` is `https://webalyzer.dev/schemas/rule-spec.json`). The `rules/` directory is retired (packs moved to `src/assets/`).

## Rule pack format gotchas
- Rule IDs MUST match `^[A-Z]{2,6}-\d{2,3}$` (e.g. `SEO-01`, `JSONLD-01`). `schema.json` enforces this and `additionalProperties: false`.
- A rule's `check.type` drives evaluation. Implemented: `selector`, `header`, `regex`, `fetch`, `composite`, `jsonld`, `unique`, `pairing`, `sequence`. `script` and `custom` are **not implemented** (engine emits an "engineError" finding for `script`).
- `jsonld` check (fully rule-driven, no static assumptions): `jsonldType` (required `@type`), `requireContextSchemaOrg` (bool), `requiredFields` (dotted/nested paths like `offers.price`), `fieldTypes` (per-path `string|number|url|boolean|date`). Paths are **array-aware**: `offers.price` validates every element whether `offers` is an object or an array. Relational assertions (all declarative, engine hardcodes no schema): `requiredGroups` (fields that must co-exist, e.g. price+priceCurrency), `conditional` (if-then: if `review` present require `review.author`), `enumValues` (allowed-value sets, e.g. availability), `patterns` (per-path regex/format, e.g. `^[A-Z]{3}$` for currency), `numericRange` (min/max/exclusiveMin, e.g. price>0), `arrayItemTypes` (validate every element of a primitive array). The engine unwraps arrays + `@graph` and **collects nested objects deeply** (an `Offer` inline in `Product.offers` is addressable via `jsonldType: "Offer"`). No field names are hardcoded — everything comes from the rule.
- Counting check types default to `threshold: {equals: 0}` (zero violations passes): `unique` (`selector`+`attribute` → count of duplicated values), `pairing` (`selector`+`attribute`+`requireSelector`/`requireAnyOf` with `{value}` interpolation; `tokenize: true` splits space-separated id lists like `aria-labelledby`; missing attribute counts as one violation), `sequence` (`selector`, `sequenceRule: "no-skip"` — level may drop freely, rise by ≤1; levels read from `levelAttribute` or the h1-h6 tag, falling back to `aria-level`).
- `each` (extension of `selector` checks): per-element attribute assertion — `allowedValues` / `pattern` / `nonEmpty`, evaluated for EVERY matched element instead of joined values. Vocabularies live in the pack. Missing attribute counts as a violation only when `nonEmpty: true`.
- `scope: "root"` rules only run when the audited URL starts with `metadata.homepage` (falls back to the URL's origin).
- Selector value extraction heuristic (`extractSelectorValue` in `engine.ts`): if `attribute` set → attribute values; else if meta tag → its `content`; else if `threshold.equals` is a **number** → element count (this is what makes `{equals: 0}` = "match nothing" work); else for small `threshold.max` (≤10) → element count; else → text length. Counter-intuitive — check before changing rule thresholds.
- `meetsThreshold` footgun: for a non-numeric string with a numeric threshold, it compares **string length**, not content. A rule like `{equals: "https://..."}` against a meta string matches on length alone. Use `contains`/`equals` with string thresholds only when length comparison is intended.
- `{{baseUrl}}` in a `fetch` check URL is interpolated with the page origin.

## Conventions
- Imports use the `#src/` alias (`deno.json` `imports`), e.g. `import { RuleT } from "#src/types.ts"`. Keep that, don't switch to relative `../` paths.
- JSON rule files use a `with { type: "json" }` import assertion (Deno 2 syntax).
- Product name is **webalyzer** (was "SiteAgent" in early code). Keep UA + schema `$id` in sync.
- Code comments and skill prose use the project's own "caveman" terse style; the `caveman` skill is in ultra mode by default per user instruction.
